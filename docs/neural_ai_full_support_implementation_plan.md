# Neural-AI Full-Support Implementation Plan

## 1. Goal and scope

Build a first-class Neural-AI target in Vela/Regor that compiles the selected,
static-shape, batch-1 INT8 YOLO and MobileNet artifacts into one relocatable
`.nai` package executable by one generic firmware image.

Allowed changes:

- `neural-compiler` compiler, tests, and documentation.
- `neural-ai/sw` ABI, runtime, kernels, tests, and simulation tooling.
- `neural-ai/hw/**/*.sv` only after explicit user approval. RTL is otherwise
  frozen; testbench and cocotb changes are allowed.

This is model-driven support, not generic TFLite/TOSA coverage. A contract is
added only when it occurs in a named release artifact, has focused positive and
negative tests, and has a measured model-path justification. Unsupported forms
must fail at compile time with the operation ID, shape, quantization, and failed
constraint. There must be no silent CPU or generic scalar fallback.

### Definition of target support

- One `.nai` file; no model-specific `main.c`, C graph, packed-weight source, or
  hand-written descriptor.
- Main tensors and weights are INT8; biases and accumulators are INT32.
- Public rank-4 bindings are compact NHWC. Native layouts remain private.
- Output is byte-exact against TFLite `BUILTIN_REF`, except where a separately
  documented tolerance is deliberately approved.
- Every selected-artifact operator instance maps to a reviewed lowering.
- Static shapes, batch 1, one cluster, and generic model-independent firmware.
- Dynamic shapes, floating point, arbitrary frontend operators, generic NMS,
  control flow, and five-cluster scheduling are out of scope.

## 2. Architectural decisions and immutable contracts

Regor's frontend, Graph IR, optimiser framework, scheduler, live-range allocator,
HLC representation, and architecture interfaces are reused. Neural-AI owns its
operator constraints, physical layouts, encoders, tiling, performance model,
commands, package writer, and runtime ABI. No separate Python compiler is added.

```text
TFLite/TOSA logical NHWC
  -> compact NHWC public input
  -> explicit boundary pack or native first consumer
  -> C32_BLOCKED / ROW32 internal tensors
  -> explicit unpack or native final producer
  -> compact NHWC public output
```

Ethos `NHCWB16` is unreachable from Neural-AI. Shared Ethos assumptions such as
16-byte alignment must be architecture-owned before they affect this target.

### Memory and package ABI

- Physical TCDM: 512 KiB.
- Final 4 KiB: command staging; allocatable TCDM is 520,192 bytes.
- Native engine tensors/references: 32-byte aligned. Compact boundary data may
  be byte-aligned where iDMA permits it.
- Firmware `.text`: strictly below 32 KiB ITCM.
- Constants stay in L2 and are staged locally only when required by an engine.
- Runtime emits canonical `0x1010...` TCDM addresses. Snitch verifies the
  `0x1010...`/`0x1018...` aliases; iDMA verifies the engine-only `0x1020...`
  alias through L2 round trips.
- `.nai` begins with `NAIV`, contains fixed-width little-endian sections and
  relocatable region/offset references, and contains no native pointers.
- ABI v2 is the only firmware command path; legacy `NPUC` parsing and its test
  firmware were removed after migrating MatMul to a V2 package/invocation.
- Regor validates semantic command constraints. Trusted firmware retains the
  structural, overflow, reference, binding, address-range, and transfer checks
  required to resolve and execute the package safely.

### Layouts and data representation

- External rank-4 layout: contiguous NHWC.
- Conv layout: `C32_BLOCKED`; logical channel tails are zero/zero-point padded.
- Matrix layout: `ROW32`.
- Compact CHW is allowed only at an explicit public boundary or a reviewed
  consumer such as the YOLO head/DFL path.
- Storage-preserving views alias only when physical interpretation remains
  unchanged. Otherwise the compiler emits one explicit materialization.
- Local-to-local regular copies use Spatz or iDMA-width transfers, never a
  Snitch byte loop or one command per byte.

### Quantization

- Native matrix/Conv requires weight zero point 0 and canonical IFM zero point
  0; OFM zero point is arbitrary signed INT8 and is applied by requantization.
- A constant-weight Conv with scalar nonzero IFM zero point may be canonicalized
  exactly by correcting each bias with `-ifm_zp * sum(weights)` and filling
  implicit padding with the original raw IFM-zero-point byte. Reject dynamic
  weights/biases, overflow, or any untested variant.
- Per-channel multiplier/shift/clamp data is generated by the compiler and must
  match TFLite integer rounding, saturation, and zero-point behavior.
- Fused ReLU/ReLU6 is a requantization clamp. Standalone activation and selected
  SiLU/Hard-Swish patterns use generated 256-byte LUTs.

## 3. Release corpus and reproducibility

Scope is defined by named artifacts, not by the frontend operator catalogue.
Each release artifact records hash, byte size, input shape, tensor quantization,
operator inventory, and source operator IDs. Generate inventories and mapping
micrographs with:

```sh
neural-ai-model-inventory model.tflite > model.inventory.json
neural-ai-model-inventory model.tflite \
  --micrograph 0:OP0,OP1,OP2 --input-hw 16x16 \
  --output mapping_case.tflite > mapping_case.provenance.json
```

The extractor preserves selected operations, constants, connectivity, channels,
weights, quantization, builtin options, and source provenance. Mapping fixtures
exercise real producer/consumer topology; isolated operations are used only when
their behavior is topology-independent.

### Verified YOLO C144 head pack

Selected transpose instances:

| Source op | Input | Permutation | Output |
|---|---|---|---|
| 197 | `[1,10,10,144]` | `[0,3,1,2]` | `[1,144,10,10]` |
| 214 | `[1,20,20,144]` | `[0,3,1,2]` | `[1,144,20,20]` |
| 231 | `[1,40,40,144]` | `[0,3,1,2]` | `[1,144,40,40]` |
| 236 | `[1,4,16,2100]` | `[0,1,3,2]` | `[1,4,2100,16]` |

The first three are one constrained contract: concatenate C64 and C80 pointwise
outputs into five physical C32 planes (C80 occupies C96 physically), then pack
only 144 logical channels into compact CHW. The inner copy uses strided vector
loads and contiguous vector stores. Other permutations, split depths, dynamic
shapes, requantization, and public intermediates are rejected.

Compiler commit `4e55d26e` defines this contract and `fad42443` lowers the three
instances. The exact op-197 fixture is 1,032 bytes, MD5
`95d092b30c2554bc857b4565a351183c`; its 896-byte package has MD5
`51474bc8b289f991feede52575ed6e58`, three commands, and requires 44,800 TCDM
bytes. TFLite `BUILTIN_REF` produces an exact 14,400-byte golden.

The package contains input NHWC-to-C32, one `C32ToCHW` command with mode 5 and
C144 valid depth, then output DMA. The focused Verilator test passes all 14,400
bytes at 155,705 total simulated ns, 125,397 ns measured invocation time, and
85,414 PMU cycles. Those cycles are 24.5% of the 347,992-cycle Micro-MobileNet
reference and 22.0% of the 388,146-cycle Micro-YOLO reference. These ratios are
focused cross-workload attribution only, not 1:1 targets. The runtime uses
strided vector loads and contiguous vector stores, with no scalar byte-copy or
command-per-byte slow path. The earlier status-4 failure was a cocotb setup bug:
the focused test had not written its invocation and binding table to L2.

## 5. Remaining work, in execution order

### Completed — exact DFL16 head pattern

The selected four-coordinate, 16-bin, 2,100-location chain is fused into one
DFL operation. The approved RTL generalization preserves DFL4 and adds DFL16;
firmware performs one Spatz gather/pack call per 32-location tile, one AFU call,
and one vector requant/pack. The three piecewise box scales are folded into the
corresponding DFL commands with exact 16-bit multiplier/right-shift pairs. Host,
block, and focused cluster tests pass. The full compiler-runtime package is
byte-exact at 445,750 cycles under the 1,000,000-cycle gate. This is 4.9% below
the earlier 468,781-cycle DFL-only reference; performance remains a regression
guide rather than a requirement to match one implementation cycle-for-cycle.
Compiler lowering now passes the box-scale Mul. Models whose exact output scale
uses a right shift below 17 retain the existing fast path for larger shifts and
use a vector-only Spatz e16-to-e32 widening path for the final requant/pack. The
selected `(51003, 8)` package is byte-exact at 463,094 cycles: about 3.9% above
the 445,750-cycle fast-path reference, but still about 1.2% below the older
468,781-cycle DFL16 reference and well below the 1,000,000-cycle gate.

## 6. Standard workflow for every increment

1. Inventory the exact source operation/topology and update its constrained
   contract in this document.
2. Add compiler positive tests and nearby rejection tests.
3. Implement compiler lowering; avoid slow paths by construction.
4. If ABI/runtime changes, update both repositories and cross-ABI checks.
5. Run host runtime tests, compiler suite, cross-builds, and firmware-size gate.
6. Build a corpus-derived fixture and compare with independent TFLite
   `BUILTIN_REF` output.
7. Start one focused Verilator simulation, report its command/session, and stop
   the Codex section immediately. Never wait for it in the same section.
8. On the next user continuation, inspect the result. If it fails, diagnose and
   repeat without claiming verification. If it passes, update evidence and
   commit the verified increment with an English commit message.
9. Compile the full graph to expose the next blocker; do not use full-graph
   Verilator as an operator-mapping test.

Keep commits reviewable and bisectable: contract/tests, compiler lowering, and
runtime support may be separate commits when independently verified. Never mix
unrelated user changes into a commit.

## 7. Test and performance gates

### Correctness gates

- Compiler: serialization goldens, layout/stride/offset formulas, quantization
  edge cases, tails, tiling, alias/liveness, positive contracts, and explicit
  adjacent rejection.
- Runtime: parser bounds, region resolution, alignment, overlap, malformed V2
  commands, trusted-build safety boundaries, and operation dispatch.
- Integration: compiler-generated `.nai` package, exact external bindings,
  independent golden, status checks, and byte-for-byte output.
- Regression order: local unit tests -> ABI/host tests -> cross-build/size ->
  focused Verilator -> micrographs -> full compile -> final full-graph run.

### Performance gates

Canonical reference totals:

- Micro-MobileNet: 347,992 PMU cycles.
- Micro-YOLO raw head: 388,146 PMU cycles.

These are attribution references, not 1:1 acceptance targets for different
graphs. Compare equivalent layers or normalized paths and separate compute,
DMA, AFU/Spatz, parsing, boundary conversion, and stall costs. Exact total-cycle
parity with hand-written fixtures is not required.

A selected hot path fails the gate if PMU attribution finds a compiler-created
slow path: scalar generic tensor loop, one-byte DMA/command stream, avoidable
materialization/layout conversion, redundant requantization, blocking transfer
where overlap is required, or an unvalidated compiler fallback. Focused package
ratios such as resize 31.0%/27.8% and MaxPool 18.8%/16.8% of the two full-graph
references are descriptive only.

## 8. Risks and controls

| Risk | Control |
|---|---|
| Shared scheduler retains Ethos assumptions | Architecture-owned layouts/alignment plus Ethos regression tests |
| Compiler/runtime ABI drift | Generated manifest, static size/offset assertions, byte goldens |
| Plausible but wrong quantization | Independent integer reference, exhaustive LUT bytes, boundary values |
| Wrong asymmetric-padding semantics | Bias correction plus raw zero-point padding tests |
| Firmware exceeds ITCM | Link-time assertion and size check on every runtime change |
| TCDM alias misuse | Snitch and iDMA alias round-trip regressions |
| Claimed overlap is still blocking | PMU/stall evidence and blocking-vs-overlap output equivalence |
| Generic fallback hides missing support | Fail-closed constraints and adjacent negative tests |
| RTL used as an expedient fix | Explicit permission gate before any `.sv` change |

## 9. Definition of done

The milestone is complete only when:

- The named full-size YOLO and MobileNet artifacts are hash-pinned and compile
  into deterministic `.nai` files with no CPU fallback or hand-written graph.
- Every operator instance maps to a documented, constrained, focused-Verilator-
  verified lowering; adjacent unsupported variants fail clearly.
- Final public I/O is compact frontend order and matches the independent golden.
- The schedule fits TCDM, firmware fits ITCM, malformed packages fail safely,
  and the trusted ABI v2-only firmware remains functional.
- PMU attribution shows no compiler-created slow path on selected hot paths;
  comparisons use equivalent work and do not require artificial 1:1 matching.
- Existing Ethos/compiler and Neural-AI software/RTL regressions pass.
- No RTL `.sv` change exists without explicit approval and independent evidence.
